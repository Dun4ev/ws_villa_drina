## Границы достоверности

Пользователь в разговоре подтвердил 3 спальни, 1 туалет и большую гостиную. Подписи на приложенном плане видны, но соответствие плана реальному объекту отдельно не подтверждено. Не выдавать оценки ChatGPT о площади дома, сауне, размерах участка и выходах из комнат за проверенные характеристики. Данных второй виллы пока недостаточно.

## Последовательность работы

1. Получить и сохранить два оригинальных макета. Сопоставить их с фотографиями и выбрать визуальное направление.
2. Составить данные каждой виллы отдельно: название, вместимость, комнаты, удобства, адрес, правила, контакты и канал бронирования. Отметить неизвестные поля; не придумывать цены и отзывы.
3. Подготовить два варианта ключевых секций для показа владельцу на общем наборе реального контента. Генерацию изображений использовать для концепций дизайна, не для подмены фотографий объекта.
4. Выбранное направление реализовать: первый экран, характеристики, галерея и планировка, удобства, расположение, запрос бронирования. Вторую виллу добавлять через ту же модель данных, когда будут материалы.
5. Проверить мобильный и настольный сценарии, клавиатуру, фокус, галерею, формы/ссылки, читаемость, скорость изображений и отсутствие выдуманной доступности дат.
6. Показать локальный результат владельцу; публикация отдельным разрешенным шагом.

## Две опорные секции

**Первый экран:** реальный вид дома, бассейна и реки, короткий заголовок, подтвержденные характеристики, основная кнопка запроса бронирования и вторичная кнопка просмотра фотографий. Не обещать мгновенное бронирование без соответствующей интеграции.

**Знакомство с виллой:** выразительная галерея и понятная планировка. Нажатие на комнату может открывать соответствующие реальные фотографии; те же действия доступны с клавиатуры и на телефоне.

21st.dev: кандидат для первого экрана [Hero with image, text and two buttons, Tommy Jepsen](https://21st.dev/@tommyjepsen/components/hero-with-image-text-and-two-buttons). Страница описывает изображение, текст и две кнопки, указывает MIT. Это кандидат по структуре; полноценное визуальное превью и исходный код компонента еще не проверены. Перед заимствованием проверить код, лицензионное уведомление и зависимости. Для галереи сначала достаточно обычной адаптивной сетки с доступным просмотром фото.

## UX, DX, AX

- UX: реальные фотографии, ясный выбор виллы и путь к запросу проживания; без лишних эффектов и автопрокрутки.
- DX: общие компоненты и отдельные данные объектов, минимум зависимостей. Стек из старого разговора является предложением, а не существующим кодом: на момент проверки здесь нет приложения и Git-репозитория.
- AX: понятные имена файлов и компонентов, реестр источников, семантические заголовки и подписанные элементы управления, воспроизводимые команды запуска и проверки в будущем README.
- При реализации основной skill: `frontend-design`; для отдельной генерации концепций: `imagegen`. Новые плагины для текущего этапа не нужны.
